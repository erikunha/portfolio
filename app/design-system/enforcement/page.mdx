# ENFORCEMENT

The checks below run in CI or local tooling. CI scheduling and local-only coverage are stated separately.

## Tokens

`app/css/theme.css` (`@theme`) is the single source of truth for brand colour.
The file declares `--color-*` custom properties; Tailwind generates matching utilities.
The token swatches on the [Tokens](/design-system/tokens) page read the
same file.

| Gate | Command | Checks |
|---|---|---|
| Contrast | `pnpm lint:contrast` | Parses `--color-*` from `theme.css`; fails if any documented pair misses WCAG AA |

Type and spacing are a maintained token layer in `app/css/theme.css`: a type scale
from `--text-xs` to `--text-7xl` with a `--text-min` floor that rises from 12px to
13px at 768px and up, spacing steps `--spacing-1` to `--spacing-16`, and a 44px
`--spacing-target` for interactive targets. `lint:contrast` checks the color pairs;
the unit tests in `app/design-system/_lib/theme-tokens.test.ts` pin the scale. Motion and z-index use utilities and named CSS classes, including arbitrary values.

## Styling

Components use Tailwind utilities and shared classes in `app/css/components.css`.
The PostCSS configuration uses `@tailwindcss/postcss`. Design-system component
directories have no CSS Modules.

## Components

| Gate | Command | Checks |
|---|---|---|
| Component docs | `pnpm check:component-docs` | Every directory under `design-system/components` has a `## Name` section in `components/page.mdx` |
| Visual regression | `tests/e2e/design-system-components.spec.ts` | Local Darwin component snapshots; ignored in CI by `playwright.config.ts` |
| A11y | `pnpm playwright test tests/a11y` | axe-core scan, zero violations |

## Cross-cutting

| Gate | Command |
|---|---|
| Lint + format | `pnpm biome ci .` |
| Types | `pnpm typecheck` |
| Content schema | `pnpm validate-content` |
| Client/RSC naming (`app`, `components`, `lib`; excludes `design-system`) | `pnpm check:client-naming` |

## Adding a New Component

1. Create `design-system/components/NewComponent/` with `.tsx`, `.test.tsx`, and `index.ts` · styled with Tailwind utilities, no `.module.css`.
2. Export it from `design-system/index.ts`.
3. Add a `## NewComponent` heading in `app/design-system/components/page.mdx` · `check:component-docs` fails if it is missing.
4. Add a local Darwin visual baseline in `tests/e2e/design-system-components.spec.ts`. CI ignores this spec; page-section snapshots and co-located component behavior tests have separate coverage.

`quality-fast` runs contrast and component-heading checks. The `performance` job runs
Lighthouse and axe; PRs enter it when the app change filter matches. `app/` and
`design-system/` changes match that filter. See `scripts/detect-changes-paths.mjs`.
