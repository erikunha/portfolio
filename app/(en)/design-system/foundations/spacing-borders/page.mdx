<h2 id="phi">Golden-ratio spacing</h2>

Page rhythm steps through one set of tokens, each the previous times `--phi` (1.618). Gaps, padding, heading margins and the two-column splits on the guitar module, `/links` and the design system all read them.

| Token | Value | Size |
|---|---|---|
| `--phi-space-1` | 0.5rem | 8px |
| `--phi-space-2` | `--phi-space-1` × `--phi` | 13px |
| `--phi-space-3` | `--phi-space-2` × `--phi` | 21px |
| `--phi-space-4` | `--phi-space-3` × `--phi` | 34px |
| `--phi-text-1` | `--text-xs` × `--phi-root` (1.272) | about 15px below 768px, 16.5px from 768px |
| `--phi-inv` | 1 ÷ `--phi` | 0.618 |
| `--phi-pair-columns` | `minmax(0, 1.618fr) minmax(0, 1fr)` | 1.618 : 1, major column first |
| `--phi-pair-columns-minor-first` | `minmax(0, 1fr) minmax(0, 1.618fr)` | 1 : 1.618, minor column first |
| `--phi-pair-flex-minor` | `0 0 calc((1 - var(--phi-inv)) * 100%)` | the minor share of a flex row |

Whole-page type does not use phi: a 1.618 step from a 13px base jumps to 21px and then 34px, too coarse for dense monospace text. Only `--phi-text-1` takes the half step, for stat values. Pairs split 1.618 : 1 from 1024px and stack below it; on a phone every level is one centered column.

<h2 id="target">Touch target</h2>

`--spacing-target` is 44px, the minimum width and height of every control. `--spacing-target-compact` is 28px for dense, non-primary controls. `--spacing-target-pointer` is 36px, the row height of the section menu from 1024px with a fine pointer and the height of the small button on a fine pointer.

<h2 id="layout">Layout tokens</h2>

Responsive tokens live in the `:root` block of `app/css/theme.css`; every page container reads them. The header, every page body and the footer share one safe zone: `--measure-page` wide, centered, with `--space-gutter` on each side, so their content starts and ends on the same vertical lines at every width.

| Token | Below 768px | From 768px |
|---|---|---|
| `--space-gutter` | `clamp(16px, 4vw, 24px)` | `clamp(16px, 4vw, 24px)` |
| `--space-page-top` | 32px | 48px |
| `--space-section` | 32px | 48px |
| `--measure-page` | 1200px (the safe zone: header, every page, footer) | 1200px |
| `--measure-read` | 72ch (line length of text blocks, never a container width) | 72ch |

Line heights: `--leading-page-tight` 1.1, `--leading-page-snug` 1.35, `--leading-body` 1.6. The page-scoped names keep Tailwind's built-in tight and snug scale intact.

`--leading` is the ratio in effect for an element and its subtree, and the line box it produces is rounded to whole pixels: `round(nearest, 1em * var(--leading), 1px)`. A component asks for a ratio by setting `--leading`, not `line-height`: a `line-height` written in the components or the utilities layer outranks the base layer, and the box it produces would stay fractional.

The ratio has to travel, because a descendant inherits the ratio and not the box: a child at a different font-size scales by the same ratio. Two rules carry it. The font-size utilities carry the ratio Tailwind pairs with the size (`text-xs` is 1/0.75), so a descendant of a `text-xs` element keeps that rhythm. And the site's own `.leading-ratio-*` classes state both the ratio and the element's own `line-height`, because a font-size utility writes `line-height` in the same layer and comes first.

A leading that is a length, the career log's 22px rhythm, the footer's 20px dmesg, does not travel that way: it reaches the descendants that inherited it, and no further. Those rules state it again for the elements inside, so the rhythm stays the one the design means.

A browser without CSS `round()` keeps the ratio, which is the render it has today.

<h2 id="borders">Borders</h2>

| Token | Value | Use |
|---|---|---|
| `--border-width` | 1px | Borders and dividers |
| `--radius-none` | 0 | Sharp controls |
| `--radius-control` | 2px | Maximum control radius |

The 2px ceiling is the control-radius token, not a claim that nothing round exists: the DAW mixer's 30px knobs are circular (`rounded-full`), and the traffic-light dots in `WindowChrome` are round dots rather than a radius token.

<h2 id="focus">Focus</h2>

Keyboard focus uses `:focus-visible` with a 2px signal outline and a 2px offset. Never remove the outline without a replacement of equal contrast.
