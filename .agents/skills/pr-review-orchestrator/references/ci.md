# CI profile (claude-review workflow)

`.github/workflows/claude-review.yml` runs this procedure when an owner, member or
collaborator comments `/claude-review` on a PR, inside `anthropics/claude-code-action`. The local procedure assumes capabilities CI does not have, so
each step maps to its CI substitute. The output contract lives in
`.github/claude-review-prompt.md`; this file only changes how the evidence is gathered.

This file describes the CI job, so it is the one place in this skill that names that job's
runtime, its tool names and the paths it reads. The procedure itself names no runtime.

## What CI has

| Capability                          | In CI                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Base checkout (trusted conventions) | repository root                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| This skill (trusted procedure)      | `/tmp/review-skill`, materialised from the default branch (a sub-PR's base may be an integration branch that edited it)                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Repository skills                  | the base checkout at the repository root carries the repository's other skills too, each with its own `SKILL.md`, so a sibling skill's method is readable in the job. Not available: the runtime's own skill catalogue and the developer's personal skills                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| PR files (data under review)        | `pr-head/`, instruction-shaped files stripped                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Installed dependencies              | none: installing would run PR-controlled code (a `.pnpmfile.cjs` loads despite `--ignore-scripts`) in a job holding the reviewer's credentials                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Subagents                           | One read-only worker type is the only subagent dispatch permission granted, and it has `Read`, `Grep`, `Glob` only. The agent definition comes from the base checkout, so a base branch could edit it; `__tests__/claude-review-ci.test.ts` pins its tool list. As a second layer the runtime's built-in subagent types are denied, because each of them inherits every tool, the inline-comment tool included; that denied set is pinned by the same test. Every project agent declares a `tools:` list without the inline-comment tool, so only the main thread can post |
| PR metadata, diff and gate results  | `/tmp/review-evidence/pr.json`, `diff.patch`, `files.txt`, `checks.txt` (starts with `UNAVAILABLE` when no valid check list came back) and `failed-run-<id>.log`. A failed metadata or run lookup leaves a marker and the step continues (`pr-unavailable.txt`, `failed-runs-unavailable.txt`); a failed `gh pr diff` falls back to the paginated files API. The job stops if both paths fail. These are written by the workflow's snapshot step before the review; the reviewer has no `gh` command that takes `--jq`, which could read its environment                                        |
| Tools                               | `Read`, `Grep`, `Glob`, `Task` and the inline-comment tool. Denied, which overrides what tag mode adds: edits, every `Bash` command including the action's git and push-wrapper tools, web tools, and reads of `.git/`, `/proc`, credential and config files in the home directory (not the home directory itself, which holds the workspace) and the runner temp directory. No `gh` command and no network fetch is granted                                                                                                                                                                    |
| Local build, browser, servers       | not available                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

The files API fallback writes filenames and patches, with a `diff --git` header for each file. Missing patches appear as `# patch omitted by GitHub: <f>`.

## Step mapping

| Local step            | CI substitute                                                                                                                                                                                                           |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Calibrate             | fixed: the table above                                                                                                                                                                                                  |
| Resolve target        | `/tmp/review-evidence/pr.json`, `diff.patch` and `files.txt`                                                                                                                                                            |
| Domain matrix         | same (`domains.md`)                                                                                                                                                                                                     |
| Skill dispatch       | the repository's skills are materialised in the base checkout at the repository root, so a matching repository skill is a track in this job; the runtime's own catalogue and the developer's personal skills are not available, so the session-skill tracks are a named limit, stated in the overview   |
| Domain tracks         | `Task` subagents, one falsifiable question each, launched in one message for independent domains. The reviewer is one agent family; say so in the overview when the change is consequential and suggest a local review. |
| Gates                 | read the snapshot; a failed or pending gate the change touches is evidence, a passed one is not proof of the journeys it does not exercise, a check pending at snapshot time is a limit                                 |
| Local run and browser | not run: the e2e, visual and LHCI jobs are the runtime evidence; anything they do not cover stays a limit; the image reader works but there is no driver, so a live capture is impossible: a track that needs a fresh capture of the change is blocked, while a track settled by reading a committed baseline or a design export is not (see `references/multimodal.md`) |
| Dependency research   | manifest and lockfile diff; overrides checked against the dependent's range as the lockfile records it; whatever needs installed source or release notes is a named limit, settled by a local review                    |
| Refute and challenge  | re-read the decisive lines yourself; one extra `Task` challenger for each CRITICAL before posting                                                                                                                       |
| Output                | the inline-comment and verdict contract in the CI prompt, never the local draft format                                                                                                                                  |

## Budget

The job has a timeout; size fan-out to it. A trivial PR needs no subagent. A dependency upgrade,
an `app/api/**` change or a cross-system PR earns one subagent per MATERIAL domain.
