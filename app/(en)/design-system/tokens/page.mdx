<h2 id="type-scale">Type Scale</h2>

The base `h1` rule uses `--font-display`, Inter at weight 900. Body text, controls
and other base headings use `--font-mono`, JetBrains Mono. Consumers can override these rules. Both stacks reference
the existing `next/font/local` variables.

| Token | Utility | Size |
|---|---|---|
| `--text-xs` | `text-xs` | 12px below 768px; at least 13px from 768px |
| `--text-sm` | `text-sm` | 14px |
| `--text-body` | `text-body` | 14px, reading text (git log, card copy); 12px stays for labels |
| `--text-base` | `text-base` | 16px |
| `--text-lg` | `text-lg` | 18px |
| `--text-xl` | `text-xl` | 20px |
| `--text-2xl` | `text-2xl` | 24px |
| `--text-3xl` | `text-3xl` | 32px |
| `--text-4xl` | `text-4xl` | 40px |
| `--text-5xl` | `text-5xl` | 48px |
| `--text-7xl` | `text-7xl` | 64px |

`--text-min` rises from 12px to 13px at 768px. `--text-xs` uses that floor.
Use these tokens for small text; fixed pixel utilities do not inherit the floor.
Sizes use rem units so they follow the reader's default font size.

The base `h1` is 32px, rising to 40px at 1280px. `h2` is 20px, rising to
24px at 768px. `h3` is 18px. Consumers can select larger steps for display text.

<h2 id="viewports">Viewports</h2>

A media query cannot read a custom property, so stylesheets write `theme(--viewport-md)` and Tailwind
substitutes the width at build time. Each step has a `below` twin 0.02px lower, so `max-width` ends
where the next `min-width` starts and no width matches both or neither.

| Step | Min width | Max width (below) | Usage |
|---|---|---|---|
| `--viewport-narrow` | 360px | 359.98px | narrowest phones |
| `--viewport-phone` | 480px | 479.98px | wide phones |
| `--viewport-md` | 768px | 767.98px | phone to tablet; matches `MOBILE_BREAKPOINT_PX` |
| `--viewport-split` | 900px | 899.98px | two-column splits |
| `--viewport-lg` | 1024px | 1023.98px | tablet to desktop; the dock hides |
| `--viewport-xl` | 1280px | 1279.98px | wide desktop |

A few queries stay literal because they mark one component's measured ladder, not a layout step: the
`content-visibility` size estimates (340, 412 and 600px), the contact grid steps (512 and 640px) and
three one-off folds (389.98, 599.98 and 1199.98px).

<h2 id="borders">Borders</h2>

| Token | Value | Usage |
|---|---|---|
| `--border-width` | 1px | Borders and dividers |
| `--radius-none` | 0 | Sharp controls |
| `--radius-control` | 2px | Maximum control radius |

Keyboard focus uses `:focus-visible` and one ring: `--focus-ring` (a 2px solid signal outline) with
`--focus-ring-offset` (2px), or `--focus-ring-offset-inset` (-2px) for a control that sits flush against its
neighbours. `app/css/base.css` applies it to links, buttons, inputs, selects, summaries and tabbable
elements, so a component does not restate it. `pnpm lint:css-tokens` fails a focus rule that writes its
own width, color or offset, or that paints the ring on plain `:focus`.

<h2 id="motion">Motion</h2>

Components use Tailwind duration and easing utilities, plus named CSS animations.
The MOTION switch is the single control. A first visit starts with motion on, even
when the operating system asks for reduced motion. Switching it off sets
`body[data-motion="reduce"]`, and every reduction is keyed to that attribute in
`app/css/animations.css`, `crt.css`, `components-*.css` and component logic. Check
the affected animation rather than assuming one global rule disables all motion.

Module headers reveal text in character steps as they enter the viewport. Their caret
blinks four times and then stays solid. The MOTION switch
disables this effect. Browsers without scroll-driven animation support show static headers.

| Utility | Value | Usage |
|---|---|---|
| `duration-[80ms]` | 80ms | micro transitions (hover, press) |
| `duration-100` | 100ms | fast UI feedback |
| `duration-200` | 200ms | standard transitions |
| `ease-out` | Shared | easing used by Button and Field |

<h2 id="layers">Layers</h2>

Every z-index is a step of the `--z-*` scale in `app/css/theme.css`; a stylesheet writes
`z-index: var(--z-drawer)` and markup writes `z-(--z-topbar)`. `pnpm lint:css-tokens` fails a literal.
Layers stack in this order:

| Layer | z-index | Usage |
|---|---|---|
| rain | `--z-rain` (0) | the Matrix rain canvas |
| CRT layers | `--z-crt-vignette` (1) to `--z-crt-beam` (5) | vignette, scanlines, mask, noise, flicker, scan beam |
| local | `--z-local` (1), `--z-local-above` (2) | stacking inside one component |
| content | `--z-content` (10), `--z-content-raised` (11) | `.page-main`, page content above the CRT overlay |
| title bar | `--z-title-bar` (109) | the phone title bar |
| header chrome | `--z-topbar` (110) | the desktop topbar and the phone status bar |
| to top | `--z-to-top` (115) | the scroll-to-top button |
| offline notice | `--z-offline` (118) | the no-signal bar; the drawer and its scrim cover it |
| dock | `--z-dock` (120) | bottom navigation dock |
| scrim | `--z-scrim` (125) | the drawer scrim behind the open menu |
| position line | `--z-position-line` (126) | the side scroll-progress line below 1024px |
| progress line | `--z-progress-line` (127) | the page-load bar on `/links` |
| drawer | `--z-drawer` (130) | the section menu drawer |
| system failure | `--z-sysfail` (9998) | the SYSTEM FAILURE plate |
| skip link | `--z-skip-link` (9999) | skip-to-content link, always on top |
