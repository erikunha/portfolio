# TOKENS

Colour, type, spacing and border tokens live in `app/css/theme.css`.
Tailwind's `@theme` generates utilities from these custom properties. Swatches
read their values directly from that file.

Tailwind's default color, radius and shadow scales are reset, so `bg-red-500`, `rounded-lg`
and `shadow-md` produce nothing. Only the tokens on this page generate those utilities.

<h2 id="color">Color</h2>

Use semantic roles for text and emphasis. The ordinal families remain available
for surfaces and existing consumers; code syntax uses the green and grey ramps.

### Semantic roles

The page background is `carbon-950`. Body text uses `text` (the same mint
as `sage-50`); signal emphasis uses `accent` (the same green as `signal-500`).
Use `text-secondary` for new secondary text instead of `signal-300`,
`signal-400` or `sage-400`. Those shades remain available for existing consumers.

### Role tokens

A role names what a color does. Each one is an alias of a primitive below, so a
stylesheet reads `var(--color-surface)` and the role keeps one meaning if the primitive moves.
Prefer a role to a primitive step in new code. Only `text` generates a utility; the other eleven
are plain custom properties on `:root`, and the print sheet remaps all twelve to ink on paper.

<h2 id="type-scale">Type Scale</h2>

The base `h1` rule uses `--font-display`, Inter at weight 900. Body text, controls
and other base headings use `--font-mono`, JetBrains Mono. Consumers can override these rules. Both stacks reference
the existing `next/font/local` variables.

`--text-min` is the floor for small text at every width, phones included. `--text-xs` uses it.
Use these tokens for small text; fixed pixel utilities do not inherit the floor.
Sizes use rem units so they follow the reader's default font size.

The base `h1` is 32px, rising to 36px at 1280px. `h2` is 20px, rising to
24px at 768px. `h3` is 18px. Consumers can select larger steps for display text.

<h2 id="viewports">Viewports</h2>

A media query cannot read a custom property, so stylesheets write `theme(--viewport-md)` and Tailwind
substitutes the width at build time. Each step has a `below` twin 0.02px lower, so `max-width` ends
where the next `min-width` starts and no width matches both or neither.

<h2 id="motion">Motion</h2>

Components use Tailwind duration and easing utilities, plus named CSS animations.
The MOTION switch is the single control. A first visit starts with motion on, even
when the operating system asks for reduced motion. Switching it off sets
`body[data-motion="reduce"]`, and every reduction is keyed to that attribute in
`app/css/animations.css`, `crt.css`, `components-*.css` and component logic. Check
the affected animation rather than assuming one global rule disables all motion.

Three custom variants in `app/css/theme.css` spell the selector, and nothing else may:
`motion-off` (switch off), `motion-on` (switch on) and `reveal-motion-on` (switch on and the
type reveal ready). A utility reads `motion-off:animate-none`; a stylesheet writes `@variant motion-off { ... }`.

Module headers (`components/responsive/Module`) reveal text in character steps as they enter
the viewport, driven by scroll position (`animation-timeline: view()` in
`components-scroll-type.css`). Their caret blinks four times and then stays solid. The MOTION
switch disables this effect. Browsers without scroll-driven animation support show static headers.

Elements marked `data-type-reveal` (panel titles with `reveal`, reading-view headings, footer
lines) use a second mechanism. The `TypeReveal` island, mounted once by `GlobalMotion` in the
root layout, adds `type-reveal-ready` to `<html>` and a class to each element when it first enters
the viewport. The text then reveals one character per step, and the caret blinks and disappears.
With the MOTION switch off, or without `IntersectionObserver`, every element shows at once. The
timing comes from tokens in the `:root` block of `app/css/theme.css`:

<h2 id="component-tokens">Component tokens</h2>

The `@theme` block also holds tokens scoped to one component. They are not a shared vocabulary, so
a new component declares its own rather than reusing another's.

| Prefix | Owner | Examples |
|---|---|---|
| `--eq-*` | the EQ curve and spectrum ([EqSpectrumStrip](/design-system/components#eq-spectrum-strip)) | plot and axis heights, bar gaps, curve stroke, level steps |
| `--guitar-*` | the guitar module | column template, photo filters and ratio, arrow size |
| `--mixer-*` | the DAW mixer | chip width, chain rows, transport gap |
| `--links-thumb-*` | the `/links` cover frame ([Cover frame](/design-system/components#cover-frame)) | contrast, brightness, tint, reveal duration |
| `--receipt-*` | the project receipts list | metric, value and company column widths |
| `--breakpoint-*` | the guitar module | the one component-owned layout width |
